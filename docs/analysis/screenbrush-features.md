# ScreenBrush 1.9.3 기능 카탈로그

조사일: 2026-10-15 · 대상: `/Applications/ScreenBrush.app` · 버전: `1.9.3 (19308)`

목적은 ScreenBrush의 기능 전체를 먼저 살펴본 뒤, 맥과 Windows에서 같은 사용감으로 구현할 기능을 선택할 수 있게 하는 것이다. 아래 목록에 있다는 사실은 구현 범위에 포함한다는 결정이 아니다. 기기 간 동기화는 현재 목표에 포함하지 않는다.

목록은 **18개 범주의 기능·설정 173개**와 **사용자 동작이 확정되지 않은 구조 후보 6개**로 구성한다. 개수는 이 문서의 분류 단위이며 제품이 공식 발표한 기능 수가 아니다.

2026-10-15 사용자가 선택한 첫 버전은 **자유 필기, 굵기, 색상, 단축키 설정, 사각형, 크기 조절이 가능한 화면 텍스트, Ctrl+드래그 영역 삭제**다. 삭제 영역과 일부라도 겹친 오브젝트 전체를 삭제한다. 개발 범위와 미결정 세부사항은 [첫 버전 요구사항](../requirements/first-version.md)을 기준으로 한다. 아래의 `부분 채택`은 항목에 묶인 세부기능 전체를 구현한다는 뜻이 아니다. 선택하지 않은 나머지 항목은 미정으로 유지한다.

## 조사 결과를 읽는 방법

- **공식**: 개발자의 Mac App Store 설명이나 버전 이력에 명시된 기능이다. 실행 검증을 뜻하지 않는다.
- **리소스**: 설치본 NIB의 제목·설명·선택지·연결 액션으로 확인했다. 현재 설정값이나 접근 가능성을 입증하지 않는다.
- **구조**: arm64 실행 파일의 Objective-C 클래스·메서드·프로퍼티와 연결했다. 동작이나 내부 알고리즘을 입증하지 않는다.
- **화면**: 실행 중인 앱의 도구 막대·옵션 탐색 항목에서 해당 UI의 표시를 확인했다. 필기 동작이 검증됐다는 뜻은 아니다.

이번 조사에서는 필기·확대·캡처·원격 제어를 실제로 수행해 검증하지 않았다. 전체 기능의 **목록과 기능별 근거를 조사**했으며, 모든 알고리즘의 역분석이나 양 OS 동작 검증을 완료한 보고서는 아니다. Settings·Shortcuts 항목은 실행 UI에서 보았지만, 자동화 선택이 패널 전환으로 이어지지 않아 내부 값은 NIB와 구조 근거로 기록했다.

## 구분이 필요한 기능과 단축키

1. **Ghost와 Quick Ghost**: Ghost는 그림을 유지한 채 다른 앱을 조작하는 모드다. Ghost에서 Fn은 임시 필기, 일반 모드에서 Fn은 임시 클릭 통과라는 설명이므로 같은 키를 하나의 고정 동작으로 옮기면 안 된다.
2. **Freeze와 화면 동결**: 제품 설명의 Freeze는 그림을 유지하는 의미로 다뤘다. 화면 캡처 동결을 확인한 것으로 쓰지 않았다.
3. **Snapshot과 FlashShot**: 전자는 그림 보관·재적용과 연결되고, 후자는 화면 캡처와 연결된다. 포함 배경·레이어의 기본 규칙은 실제 파일 검증이 남았다.
4. **Scissors와 Eraser**: 둘 다 삭제 기능이지만 선택 단위와 선 일부 지우기 여부는 실기 관찰이 필요하다.
5. **Glue**: 결합 기능은 확인했으나 그룹·합성·개별 편집 복원 여부는 미확인이다.
6. **단축키**: 현재 공식 설명에는 텍스트 `Fn+T`, 확대 `Fn+Z`; 과거 이력에는 `Option+T`, `Option+Z`가 등장한다. 실제 설치본의 사용자 지정값을 읽지 않았으므로 기본키로 확정하지 않았다. 다른 공식 조합도 공개 설명상의 예시이며 현 설정과 일치한다고 주장하지 않는다.
7. **Plus**: 공식 설명이 별도로 Plus로 묶은 것은 Freeze, 화살표·직선·사각형·타원·텍스트, Undo/Redo다. 나머지 세부기능을 모두 무료라고 판정하지 않았다. 구매·라이선스 구현은 분석 대상에서 제외했다.

## 구현 범위 결정에 사용하는 방법

1. 위 기능 ID별 채택 상태를 기록하되, 현재 사용자 결정과 부분 채택 범위는 [첫 버전 요구사항](../requirements/first-version.md)을 우선한다. 색상 변경은 필수지만 색상환·슬롯 등 UI 방식은 미정이다.
2. 선택한 기능의 입력·출력·상태 전환·설정 기본값을 실제 ScreenBrush에서 관찰한다.
3. 관찰만으로 모호한 필기·편집 규칙을 REA/Hopper로 좁혀 분석한다.
4. 자체 공통 데이터·렌더링 코드와 OS별 창·입력 처리로 구현하고 양 OS에서 같은 사용감을 확인한다.

UI 프레임워크는 아직 확정하지 않았다. 첫 버전 기능은 위 요구사항 문서로 확정했으며, 전체 카탈로그를 구현하는 결정으로 해석하지 않는다.
