# My Brush 도구 막대와 입력 설계

작성일: 2026-10-15

## 문서의 상태

[첫 버전 요구사항](../requirements/first-version.md)의 7개 기능을 조작 가능한 형태로 구체화한 설계안이다. 사용자가 확정한 기능 범위와 Ctrl+드래그의 전체 오브젝트 삭제 원칙은 그대로 유지한다. 아래 기본값·키 배치·세부 판정은 이번 설계에서 정한 제안이며 사용자에게 별도로 선택받은 값은 아니다.

[브라우저 시안](../../preview/index.html)은 이 설계를 검토하기 위한 독립 HTML이다. 실제 화면 위 표시, 다른 앱으로의 입력 전달, 전역 단축키 등록을 구현한 데스크톱 앱은 아니다. ScreenBrush의 코드·이미지 자산을 가져오지 않고 요구한 기능에 맞춰 새로 작성한다.

현재 실행 구현은 별도의 Python·Qt 데스크톱 앱이다. [실행 안내](../../README.md)와 [데스크톱 검증 기록](native-verification.md)을 참고한다. 아래 브라우저 관련 설명·검증 결과는 이전 시안에 한정한다.

## 도구 막대

화면 위에 작은 가로형 막대를 둔다. 일반 작업으로 돌아가는 버튼은 필기 도구와 구분해 막대 끝에 배치한다. 창이 좁으면 줄을 나눠 표시한다.

| 순서 | 조작 | 동작과 초기값 |
|---|---|---|
| 1 | 펜 / 사각형 / 텍스트 | 한 번에 하나 선택. 초기 도구는 펜 |
| 2 | 색상 | 기본 8색과 직접 색상 선택. 불투명 단색 |
| 3 | 선 굵기 | 1~32 DIP, 초기 4. 펜과 사각형에 공통 적용 |
| 4 | 글자 크기 | 12~144 DIP, 초기 28. 텍스트 도구에서 표시 |
| 5 | 단축키 설정 | 조합 입력, 중복 확인, 저장·취소 |
| 6 | 작업 복귀 | 필기 화면을 숨기고 원래 작업으로 돌아감 |

DIP는 화면 배율과 독립적인 논리 좌표 단위다. 브라우저 시안에서는 CSS px를 대응 단위로 사용한다. 실제 앱에서는 OS 배율을 반영해야 한다.

도구·색·굵기를 바꾸면 이후 만드는 오브젝트에 적용한다. 진행 중인 한 획이나 사각형의 속성은 누르기 시점의 값으로 고정한다. 예외적으로 편집 중인 텍스트의 색과 크기는 해당 편집 내용에 적용한다. 이미 완료된 다른 오브젝트까지 일괄 변경하지 않는다.

사각형은 채움 없는 테두리로 그린다. 사각형 내부를 클릭하는 것만으로 이동·크기 변경을 시작하지 않는다. 텍스트는 다시 편집할 수 있지만 일반 오브젝트 이동·변형 기능을 함께 추가하지 않는다.

## 필기 시작과 작업 복귀

| 상태 | 보이는 것 | 입력 대상 |
|---|---|---|
| 필기 중 | 도구 막대와 필기 오브젝트 | My Brush 필기 화면 |
| 작업 복귀 | 필기 화면을 숨김 | 원래 사용하던 앱 |

작업 복귀 후에도 오브젝트는 현재 실행 세션의 메모리에 남는다. 다시 필기를 시작하면 같은 위치에 표시한다. 앱 종료 후 오브젝트 복원·파일 저장은 이번 범위에 넣지 않는다. 색·굵기·텍스트 크기·단축키 설정은 가능한 경우 기기에 저장한다.

네이티브 앱에서는 전역 토글로 필기를 시작·숨김 처리하고, 작업 복귀 때 이전 앱으로 포커스를 돌려주는 흐름을 검증한다. 브라우저 시안의 복귀 버튼은 시안 안에서만 상태를 바꾼다. 실제 바탕화면 조작이나 다른 앱 활성화를 수행하지 않는다.

네이티브 앱의 OFF 상태는 애플리케이션 활성화 이벤트만으로 해제하지 않는다. 단축키·메뉴·명시적인 앱 열기로만 다시 켜며, 필기 화면과 도구 막대를 함께 표시·숨긴다. 도구 막대의 버튼 이름은 `필기 끄기`, 메뉴는 현재 상태에 따라 `필기 켜기` 또는 `필기 끄기`로 표시한다.

작업 복귀나 토글로 숨기기 전에는 미완료 그리기·삭제 제스처를 명시적으로 취소하고 포인터 캡처를 해제한다. 포커스 상실 이벤트 발생에 의존하지 않는다. 숨김 뒤 도착한 버튼 해제로 삭제나 새 오브젝트가 확정되면 안 된다.

## 포인터 입력

| 입력 | 시작 조건 | 완료 |
|---|---|---|
| 펜 드래그 | 펜 선택 후 왼쪽 버튼 누름 | 버튼을 놓으면 한 획 저장 |
| 사각형 드래그 | 사각형 선택 후 왼쪽 버튼 누름 | 버튼을 놓으면 사각형 하나 저장 |
| 텍스트 클릭 | 텍스트 선택 후 빈 위치 클릭 | 편집기 표시 후 확정 |
| 기존 텍스트 클릭 | 텍스트 도구로 기존 텍스트 클릭 | 내용·색·크기 재편집 |
| Ctrl+드래그 | 편집기가 없는 필기 영역에서 Ctrl을 누른 채 왼쪽 버튼 누름 | 삭제 대상 미리 표시 후 버튼을 놓으면 일괄 삭제 |

도구 막대·설정 창·텍스트 편집기 위에서 Ctrl+드래그해도 삭제를 시작하지 않는다. 일반 획을 그리던 중 Ctrl을 누르는 경우에도 삭제로 전환하지 않는다. 먼저 현재 제스처를 끝내고 다음 누르기부터 적용한다.

활성 제스처는 포인터를 캡처해 필기 영역 밖에서 마우스를 놓아도 종료한다. 포커스 상실, 포인터 취소, Escape는 아직 완료하지 않은 제스처를 버린다. 이전에 완료한 오브젝트는 유지한다. 포커스를 잃은 뒤 돌아왔다고 자동으로 그리기를 재개하지 않는다.

## Ctrl+드래그 삭제

삭제 단위는 펜의 한 획, 사각형 하나, 텍스트 오브젝트 하나다. 삭제 영역과 일부라도 겹치면 그 오브젝트 전체를 제거한다.

1. Ctrl을 누른 채 왼쪽 버튼을 누르면 현재 도구를 유지하면서 삭제 제스처를 시작한다.
2. 시작점과 현재점 사이에 반투명 사각 영역을 표시한다. 어느 방향으로 드래그해도 같은 영역을 얻는다.
3. 영역에 걸린 오브젝트를 강조해 삭제 대상을 미리 보여준다. 아직 데이터는 제거하지 않는다.
4. Ctrl이 눌린 상태로 왼쪽 버튼을 놓으면 대상 전체를 한 번에 삭제한다.
5. 원래 선택한 도구로 다음 작업을 계속한다. 삭제 영역 자체는 저장하지 않는다.

Ctrl을 먼저 떼거나 Escape·포커스 상실·포인터 취소가 발생하면 삭제를 취소한다. 우발적인 Ctrl+클릭은 삭제로 취급하지 않는다. 유효 영역은 가로·세로 모두 0보다 크고 시작점부터의 직선 거리가 2 DIP를 초과해야 한다. 각 축이 2 DIP를 넘어야 하는 조건은 아니므로 길고 얇은 영역도 사용할 수 있다.

### 겹침 판정

| 대상 | 판정 영역 | 삭제하지 않는 예 |
|---|---|---|
| 펜 | 실제 선분과 선 굵기의 반경. 둥근 끝과 연결부 포함 | 획의 바깥 경계 상자만 겹치고 실제 선에서 떨어진 영역 |
| 사각형 | 네 테두리 선분과 선 굵기의 반경 | 채움 없는 사각형의 빈 내부에만 놓인 삭제 영역 |
| 텍스트 | 줄바꿈과 글자 크기를 반영한 전체 레이아웃 상자 | 표시 상자 밖의 영역 |

경계에 닿는 경우도 겹침으로 본다. 텍스트는 글자 픽셀별 윤곽까지 비교하지 않으므로 글자 사이 빈 공간도 같은 텍스트 상자에 포함된다. 객체 경계 상자는 후보 검색에 사용할 수 있지만 선·사각형의 최종 판정을 대신하지 않는다.

macOS에서 Control+왼쪽 입력이 보조 클릭으로 전달되는 경우와 컨텍스트 메뉴 처리는 네이티브 구현 초기에 검증해야 한다. 이 설계는 요구한 Control 키를 그대로 사용하며 Command로 치환하지 않는다. 브라우저 시안의 동작만으로 macOS 바탕화면에서도 동일하게 처리된다고 판단하지 않는다.

## 텍스트 입력과 크기 조절

텍스트 도구로 클릭하면 해당 위치에 여러 줄 편집기를 연다. Enter는 줄바꿈, Ctrl+Enter는 확정이다. 한글 조합 중에는 도구 단축키·Escape 취소·Ctrl+Enter 확정을 실행하지 않아 조합 처리를 방해하지 않는다.

| 상황 | 처리 |
|---|---|
| 새 텍스트 확정 | 내용이 있으면 오브젝트 생성. 빈 내용이면 생성하지 않음 |
| 기존 텍스트 편집 | 편집 전 값을 보관하고 임시 내용·색·크기를 미리 표시 |
| 기존 텍스트를 비운 뒤 확정 | 해당 텍스트 오브젝트 제거 |
| Escape | 신규 편집을 버리거나 기존 텍스트를 편집 전 상태로 복구 |
| 편집기 밖 캔버스 클릭 | 편집 확정 후 해당 클릭을 소비. 다음 클릭부터 새 동작 시작 |
| 도구 전환 | 현재 편집을 확정한 뒤 새 도구 선택 |
| 설정 창 열기 | 현재 편집을 확정한 뒤 설정 창에 포커스 이동 |
| 작업 복귀 | 현재 편집을 확정한 뒤 필기 화면 숨김 |
| 크기·색 변경 | 편집 중인 텍스트에 즉시 미리 적용. 확정·취소와 함께 반영·복구 |

완료한 텍스트의 크기를 바꾸려면 텍스트 도구로 그 텍스트를 다시 클릭하고 크기 값을 조절한 뒤 확정한다. 기본 글꼴은 OS 기본 산세리프를 사용한다. 맥과 Windows의 동일한 조작 흐름을 목표로 하되 글꼴 픽셀까지 같은 결과를 전제하지 않는다.

## 단축키

아래는 기본 배치안이다. 별도 고정 입력을 제외한 7개 동작을 설정 창에서 변경할 수 있다.

| 동작 | 기본 조합 | 적용 범위 |
|---|---|---|
| 필기 켜기 / 끄기 | macOS: Ctrl+Cmd+Tab · Windows: Ctrl+Shift+Space | 네이티브 전역. 이전 브라우저 시안은 Ctrl+Shift+Space 유지 |
| 펜 | B | 필기 중이며 텍스트·설정 입력을 하지 않을 때 |
| 사각형 | R | 위와 같음 |
| 텍스트 | T | 위와 같음 |
| 선 굵기 감소 | [ | 위와 같음 |
| 선 굵기 증가 | ] | 위와 같음 |
| 단축키 설정 | Ctrl+, | 필기 중이며 입력을 하지 않을 때 |

기본 문자 키는 키보드의 물리 위치(`event.code`에 대응)를 사용해 한글 자판에서도 같은 위치로 전환할 수 있도록 설계한다. 실제 설정 화면에는 사용자가 알아볼 수 있는 키 이름을 표시한다. 텍스트 편집기나 설정 입력란에서는 B/R/T/대괄호를 일반 입력으로 처리한다. IME 조합·자동 반복 키로 도구 전환을 반복 실행하지 않는다.

Ctrl+드래그, Escape, 텍스트의 Enter·Ctrl+Enter는 입력 규칙으로 고정한다. 설정 대상은 위 7개 호출 동작이며 삭제 제스처의 키 변경 UI는 이번 설계에 포함하지 않는다.

설정 창은 조합을 누르면 임시값을 기록하고 저장 전까지 기존 설정을 사용한다. 단독 보조키, 동작 간 동일 조합, 고정 입력과 충돌하는 조합은 오류를 표시하고 저장하지 않는다. 취소하면 변경을 버린다. 저장한 조합을 버튼 도움말에도 반영한다.

OS가 점유한 전역 조합인지 여부는 네이티브 등록 결과로 판단한다. 등록에 실패하면 이유를 표시하고 기존 조합을 유지한다. 브라우저의 중복 검사 통과는 OS 전역 등록 성공을 뜻하지 않는다. 일반 도구 키를 작업 복귀 상태에서 다른 앱 입력으로부터 가로채지 않는다.

최초 등록에 실패하면 유지할 기존 조합이 없으므로 앱 메뉴의 ‘필기 시작’을 대체 진입으로 제공한다. 키가 등록되지 않았다는 상태를 표시하고 설정을 다시 열 수 있어야 한다. 이 대체 진입을 확인하기 전에는 필기 화면을 숨겨 접근할 수 없게 만들지 않는다. 시안은 별도의 다시 시작 버튼으로만 복귀 흐름을 보여준다.

## 취소와 입력 우선순위

Escape 한 번에 가장 안쪽의 활성 상태 하나만 닫는다.

1. IME 조합 중이면 조합 입력에 맡긴다.
2. 키 조합 기록 중이면 그 기록을 취소한다.
3. 설정 창이 열려 있으면 저장하지 않고 닫는다.
4. 텍스트 편집 중이면 해당 편집을 취소한다.
5. 그리기·삭제 제스처 중이면 해당 제스처만 취소한다.
6. 그 외 필기 중이면 작업으로 복귀한다.

설정 창·편집기와 활성 그리기 제스처가 동시에 입력을 받지 않게 한다. 도구 막대에서 시작한 포인터 입력을 캔버스 입력으로 재사용하지 않는다.

| 도구 | 펜 한 획, 네 방향 사각형, 도구 전환 |
| 속성 | 새 오브젝트의 굵기·색 적용, 진행 중인 제스처 속성 고정 |
| 텍스트 | 여러 줄·한글 입력, 생성·기존 편집·크기 변경, 확정·취소·외부 클릭 소비 |
| 영역 삭제 | 여러 종류 동시 삭제, 일부 교차·경계 접촉·두꺼운 선 끝·역방향·길고 얇은 영역 |
| 삭제 제외 | 사각형 빈 내부, 곡선의 빈 경계 상자, 영역 밖, 단순 클릭 |
| 삭제 취소 | Ctrl 먼저 해제, Escape, 포커스 상실, 포인터 취소 |
| 숨김 중 취소 | 그리기·삭제 드래그 중 토글 → 숨김 후 버튼 해제 → 재표시 시 미완료 결과가 남지 않음 |
| 단축키 | 기본 키, 변경·저장·취소·중복, 입력란·IME에서 도구 키 제외 |
| 화면 | 데스크톱 크기와 360px 폭에서 핵심 조작 접근 |

데스크톱 구현을 시작할 때는 맥과 Windows에서 투명 최상위 창, 필기 입력과 일반 앱 복귀, 전역 토글, macOS Control+드래그를 먼저 검증한다. 이어서 다중 모니터·배율·전체 화면 앱·포커스 복귀·실제 한글 IME를 OS별로 확인한다. 브라우저 시안 결과로 이 항목들을 완료 처리하지 않는다.

Undo/Redo, 전체 삭제, 화살표, 자동 사라짐, 내보내기 등은 추가하지 않는다. 구현은 Qt Widgets·QPainter와 OS별 단축키·포커스 연동을 사용하고, PyInstaller로 각 OS에서 번들한다. 실제 실행 검증 상태는 데스크톱 검증 기록을 따른다.
